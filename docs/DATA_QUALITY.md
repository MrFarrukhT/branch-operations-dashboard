## Issues and how they were handled

### 1. 2025-Q3 is incomplete: 4 of 6 segments reported

**Severity:** high · **Category:** completeness

- **In short:** 2025-Q3 has no rows for South · Standard and West · Standard (2 of 6 segments). Nothing was estimated; the quarter is marked as partial.
- **Found:** No row exists for South · Standard and West · Standard in 2025-Q3. Every other quarter has all 6 region × tier segments, so 2025-Q3 totals (revenue, active clients, tickets) are not comparable with earlier quarters. The prior-quarter flow would put their opening active clients at South · Standard ≈ 292, West · Standard ≈ 309.
- **Handling:** Rows are NOT imputed. The dashboard flags the quarter as partial on the trend chart and in a notice, and offers a "Complete data only" switch that keeps only segments reported in every selected quarter.
- **Why:** Revenue, tickets and resolution time cannot be derived from other columns, and a guessed number would look exactly like a real one. Showing the gap keeps every figure on screen traceable to a source row.

### 2. Region names in mixed case

**Severity:** medium · **Category:** consistency · **Records:** 102, 106

- **In short:** 2 rows had a region name in the wrong case ("north", "WEST"). Corrected.
- **Found:** record 102 has "north" (→ North); record 106 has "WEST" (→ West). Grouped as-is, "North" and "north" would become two separate regions.
- **Handling:** Matched case-insensitively against the known regions (North, South, West) and rewritten in canonical Title Case.
- **Why:** The branch name confirms the region in every affected row (each branch appears under exactly one region elsewhere), so the correction is certain, not a guess. Unknown spellings would be rejected rather than coerced.

### 3. Missing average resolution time

**Severity:** medium · **Category:** completeness · **Records:** 106

- **In short:** One row had no resolution time ("N/A"). Left blank and excluded from the resolution-time average.
- **Found:** record 106 has avg_resolution_hrs = "N/A" — a text placeholder in a numeric column. The row's other fields are complete.
- **Handling:** Stored as null (not 0). The record stays in every other KPI; the resolution-time average is taken over records that have a value, and the card says how many were excluded.
- **Why:** Zero would claim the tickets were solved instantly and drag the average down; dropping the whole row would lose valid revenue and client figures. Filling from neighbours would invent a measurement.

### 4. Mixed number precision in avg_resolution_hrs

**Severity:** low · **Category:** format · **Records:** 114

- **In short:** One row gave the resolution time with a different number of decimals. Same value; nothing changed.
- **Found:** Most values carry 1 decimal place, but record 114 does not (e.g. "6" where "6.0" is expected).
- **Handling:** Parsed as numbers, so "6" and "6.0" are the same value. Display precision is set by the UI, not the source.
- **Why:** Harmless to the maths, but it hints at a hand-edited or differently exported row, worth telling the data owner.

### 5. File format

**Severity:** info · **Category:** format

- **In short:** The file has Windows line endings and no line break after the last row. Read correctly; no rows affected.
- **Found:** The file uses CRLF (Windows) line endings, no newline after the last row.
- **Handling:** The parser accepts CRLF and LF, a missing final newline and a BOM; blank lines are skipped.
- **Why:** A naive split on "\n" leaves "\r" glued to the last column ("4.2\r"), which turns numbers into text. Handled in the parser so no value is affected.

### 6. Active clients is a point-in-time count

**Severity:** info · **Category:** interpretation

- **In short:** Active clients is a start-of-quarter count, so the card shows the latest complete quarter, not a sum of quarters.
- **Found:** In all 10 consecutive-quarter pairs, next quarter's active_clients = active + new − churned of the quarter before, so active_clients is the opening client base of each quarter.
- **Handling:** Active clients (sum) adds up the filtered rows. The Active clients card shows the latest complete quarter; with several quarters selected, the sum is given beneath it on its own line ("3-quarter sum").
- **Why:** The same client is counted once per quarter, so a multi-quarter sum is not a head count. The identity also validates the data: it holds for every pair of rows the file lets us check.
